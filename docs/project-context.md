# 钢贸上下游数据平台：项目背景与已确认决策

相关文档：[需求文档](./steel-trade-data-platform-requirements.md)

## 目标

为货袋子平台新增一个板块：钢贸行业上下游数据平台。下游钢贸企业通过 ERP 调用平台接口上传销售与库存数据，上游钢厂付费查看聚合后的数据。

## 固定约束

- 平台需支持海量数据。
- 下游钢贸企业（数据上传方）至少 20000 家，上游钢厂（数据购买方）至少 500 家。
- 后端 Java，前端 Vue3。
- 作为货袋子平台的一个板块融入，货袋子平台现状信息尚未提供（见需求文档第 22 章）。
- 上游只能看聚合数据，看不到单家企业明细。
- 只向上游收费，按下游企业数计费，支持批量购买。

## 原型范围（2026-11-24 确认）

- 高保真 HTML 原型覆盖三端：上游厂家端（2026-11-26 前称“上游钢厂端”）、下游钢贸端、平台运营后台。
- 视觉风格先用通用的企业级后台风格，之后再向货袋子对齐。

## 原型评审中确认的规则（2026-11-25）

- 订阅期内加购名额：从新增下游企业的生效日起计费，下单日到生效日之间不收费。新增企业仍按数据池调整规则在下一周期生效。
- 价格功能尚未对上游开放时，企业名单和选购名录里的“是否提供价格数据”一列隐藏，开放后再显示。需求文档中 UP-01 与 UP-70 的冲突按此统一。

## 激励与推广模式调整（2026-11-25）

修订 D-02，并新增两项决策。上面表格中 D-02 的“收益分成”以本节为准。

- 取消下游现金收益分成。下游激励改为：钢厂带动 + 免费行业对标数据。原计划分给下游的预算改为奖励带动入驻的钢厂，形式为名额或折扣，具体数值待定。
- 推广由钢厂自己发起，不依赖平台运营逐家邀请。钢厂可批量邀请自己的协议户，并把数据报送写进年度代理协议；一级代理可继续邀请自己的二级经销商。平台运营只做支持和审核。
- 钢厂对自己带动入驻的协议户，只能看聚合数据，另外可以看每家是否已接入、报送是否达标，看不到单家数据内容（销量、库存、价格都不可见）。达标指标只反映及时性、连续性等报送行为，不能让人反推数量。
- 原因：分成金额对钢贸企业不构成动力，还会把关系变成“卖数据”，加重其对钢厂查窜货、压返利的顾虑；平台自身力量不足以逐家推动 2 万家下游。
- 文档和原型统一使用的功能名称：上游端“协议户邀请与接入”，下游端“邀请下级经销商”，运营后台“带动奖励规则”。

## 分品类的统计维度与计量单位（2026-11-25）

销量和库存量按品类使用不同的统计维度：

| 品类 | 统计维度 |
|---|---|
| 管材 | 规格 + 壁厚 |
| 板材 | 厚度 + 宽度 |
| 建材 | 规格 |
| 型材 | 规格 + 公斤段或负差段 |
| 其他品类 | 规格 |

- 计量单位：钢材按吨位统计，非钢材按数量统计，两者不合并相加。
- 维度细化后，防反推规则（最小格子企业数等）照常适用；格子不足时按段或上一级维度上卷。分段方式待定。

## V0.4 评审中确认的四项（2026-11-25）

编号对应需求文档 21.3 节。

| 编号 | 事项 | 决策 |
|---|---|---|
| N-29 | 钢厂带动的协议户是否占用该厂付费名额 | 照常占用付费名额，带动奖励的名额或折扣可以抵用 |
| N-35 | 零申报是否算按时报送 | 不认可零申报，只有实际数据才算报送 |
| N-36 | 钢厂能看到协议户的哪些状态 | 已接入、是否达标，以及报送中断、已暂停、已退出 |
| N-46 | 型材的第二个统计维度 | 按品名固定：有的型材用公斤段，有的用负差段，在品类主数据里逐个品名配置 |

- N-35 的落地方式（协调方暂定，已告知业务方，等其异议）：每日库存快照也算实际数据，当天没有销售的企业只要报了库存就算报送；钢厂仍然只看到周期内达标或未达标的二值结果，看不到达标率数值。目的是不让达标结果反映单家有销售的天数。

## V0.5 评审中确认的两项（2026-11-25）

编号对应需求文档 21.4 节。

| 编号 | 事项 | 决策 |
|---|---|---|
| N-53 | 什么数据算当日已报送 | 库存快照或销售数据任一即可（与文档 V0.5 现行写法一致，由暂定改为已确认）。业务方没有采纳“库存快照为必要条件”的建议 |
| N-54 | 常年不落库的企业（直发、订单贸易）怎么评定达标 | 企业申报、运营核实后标记为“无库存经营”，达标显示“不适用”；申报时告知企业，钢厂会看到这个标记 |

- 上面“V0.4 评审中确认的四项”里 N-35 的落地方式，随 N-53 的确认不再是暂定。
- 保留的残余风险：只报销售不报库存、上传范围很窄的企业，达标结果仍会反映有业务的天数是否足够。靠宽松的达标阈值（N-34，待定）缓解。

## 端名称与多维查询的修改要求（2026-11-26）

业务方原话：“在上游钢厂端，请把名称改为：上游厂家端；在上游厂家端里面多维查询里面的查询在规格端需要增加壁厚查询，因为管材必须要使用壁厚，而板材在壁厚的基础上，则需要增加规格端。请优化”

- 端名称：“上游钢厂端”改为“上游厂家端”，简称“厂家端”。目前只改端的名称，“钢厂”这一角色称谓和购买资格是否调整待定（N-61）。
- 多维查询：品类下钻到规格段时带出第二维度。管材为规格段 × 壁厚段；板材为厚度段 × 宽度段。筛选区的按段条件在任何行维度下都生效。
- 以下是按推断处理的，等业务方确认（需求文档 21.6 节）：“规格端”按“规格段”理解；板材那半句按“在厚度段的基础上增加宽度段”理解（N-62）；管材格子不足时先把规格合并到规格段、保留壁厚（N-63）；条件只能按段选，不能输入具体数值。
